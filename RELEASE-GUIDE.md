# How to create Nhtml Release Packages

This guide explains how to bundle Nhtml for end-users based on their installation target.

## 📦 1. PHP Release Package (The "Adapter" Pack)
Target: WordPress developers, CMS users, Shared hosting users.

**Files to include:**
- `NhtmlCompiler.php` (from `nhtml_engine/`)
- `nhtml.exe` (Windows binary)
- `libnhtml_core.so` (Linux binary)
- `nhtml_core.dll` (FFI dynamic lib)

**User Instructions:**
"Unzip these files into your project and `require_once 'NhtmlCompiler.php';`."

---

## ⚡ 2. Direct Server Package (The "Core" Pack)
Target: System administrators, VPS users.

**Files to include:**
- `nhtml` (Native binary for target OS)
- `.htaccess` example file (for Apache)

**User Instructions:**
"Copy the binary to your server PATH and configure Apache/Nginx to handle .nhtml extensions."

---

## 🛸 3. Frontend / PWA Package (The "WASM" Pack)
Target: SPA developers, VanillaJS users.

**Files to include:**
- `nhtml.js` (The bootstrapper)
- `pkg/` (The WASM files generated by `wasm-pack`)

**User Instructions:**
"Include `nhtml.js` as a module and serve your `.nhtml` files as static assets."

---

# 🇫🇷 Comment créer les "Releases"

## 1. Pack PHP
Inclure le `NhtmlCompiler.php` et les binaires/bibliothèques dynamiques pour tous les OS.

## 2. Pack Serveur Direct
Inclure uniquement le binaire natif et les exemples de configuration.

## 3. Pack Frontend
Inclure le `nhtml.js` et le dossier `pkg/` contenant le WebAssembly.
