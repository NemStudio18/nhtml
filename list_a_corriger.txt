## **1. 🔴 Memory Leak — Accumulation de `clone()` sans limite**

**Localisation**: `src/compiler/handler_table.rs` + `src/compiler/mod.rs` (lignes 43-542)

```rust
// Dans collect_entries
if has_n_attrs {
    table.insert(HandlerEntry {
        node_id : node.id,
        n_id    : n.n_id.clone(),           // ❌ Clone 1
        handler : n.primary_handler().map(str::to_string),  // ❌ Clone 2
        n_model : n.n_model.clone(),        // ❌ Clone 3
        n_text  : n.n_text.clone(),         // ❌ Clone 4
        n_live  : n.n_live,
        listen,
    });
}
```

Pour chaque nœud avec attributs `n-*`, on fait **4+ clone()** de String. Sur un DOM avec **10,000 nœuds**, ça fait **40,000+ allocations**.

**Problème**: Dans `src/socket/mod.rs` ligne 567-626, chaque EVENT déclenche:
```rust
session.handler_table.nid_map.get(nid)  // HashMap lookup
for (nid, val) in obj {
    session.sm.update_node(
        session.state.session_id.clone(),  // ❌ Clone supplémentaire
        *target_id as u32,
        nid.clone(),  // ❌ Clone supplémentaire
        val_str.to_string(),  // ❌ Conversion String
        false
    ).await.ok();
}
```

**Recommandation**:
- ✅ Utiliser `Cow<'static, str>` au lieu de `String` pour les constantes
- ✅ Éviter les clone() dans les boucles d'événements

## **2. 🔴 Unsafe Cast — Truncation Silencieuse (Integer Overflow)**

**Localisation**: `src/socket/mod.rs` (ligne 652 et autres)

```rust
// Session IDs arbitraires peuvent être très longs
let tsid_len = pkt_data[0] as usize;  // ❌ u8 → usize (OK)
if pkt_data.len() >= 1 + tsid_len {
    let tsid = String::from_utf8(pkt_data[1..1+tsid_len].to_vec())...
}
```

**Risque**: Si un client envoie `tsid_len = 255` mais le paquet ne contient que 100 bytes:
```
pkt_data.len() = 150
1 + tsid_len = 1 + 255 = 256
256 > 150 → Skip silencieux (pas d'erreur loggée !)
```

**Pire cas**:
```rust
let node_id = u16::from_be_bytes([data[offset], data[offset+1]]);  // ❌ Pas de bounds check
let op_type = data[offset + 2];  // ❌ Peut être out of bounds
```

**Recommandation**:
```rust
if data.len() < offset + 2 {
    warn!("Packet truncated at offset {}", offset);
    return;
}
let node_id = u16::from_be_bytes([data[offset], data[offset+1]]);
```

## **3. 🟡 Logic Bug — Broadcast Validation Incorrecte**

**Localisation**: `src/socket/mod.rs` (lignes 640-660, anciennement)

```rust
// Dans la version dev-0.7.0 corrigée (à vérifier)
let should_send = match scope_type {
    proto::SCOPE_OTHERS => (sender_sid != session_id, pkt_data.to_vec()),
    proto::SCOPE_ALL => (true, pkt_data.to_vec()),
    proto::SCOPE_ROOM => {
        if pkt_data.len() > 0 {  // ⚠️ Pas de check sur 1 + rid_len
            let rid_len = pkt_data[0] as usize;
            if pkt_data.len() >= 1 + rid_len {
                let rid = String::from_utf8(pkt_data[1..1+rid_len].to_vec())...

```

**Bug**: Si `rid_len = 10` mais `pkt_data` = `[10, x, y, z]` (seulement 4 bytes), le slice `pkt_data[1..11]` **panique** (bounds check à runtime).

**Status v0.7.0**: Message "Industrial Hardening: ... Broadcast validation..." suggère que **c'est corrigé**, mais le code reste prudent.

## **4. 🔴 Concurrency Issue — Race Condition dans `last_seq`**

**Localisation**: `src/socket/mod.rs` (lignes 842-868)

```rust
// Thread 1 & 2 simultanément reçoivent EVENT seq=100
if seq_id <= last_seq {  // ❌ Check non-atomique
    warn!("[{}] REJET: Replay attack...", session_id);
    return result;
}

// Les deux threads passent le check (last_seq = 99)
let _ = session.sm.update_seq_id(session_id, seq_id).await;  // ❌ Update non-atomique
```

**Scénario**:
- Client envoie EVENT seq=100
- Gateway démarre PHP processing
- **Client envoie EVENT seq=100 AGAIN** (replay)
- Thread 2 lit `last_seq = 99` (car Thread 1 n'a pas encore fait update)
- **BOTH threads acceptent seq=100** ❌ Replay attack réussit

**Fix v0.5.0 promis**: "Atomic Sequence ID" ✅ (déjà mentionné dans docs)

## **7. 🔴 Potential OOM — Unbounded Broadcast Channels**

**Localisation**: `src/main.rs` (lignes 85-86)

```rust
let (tx_monitor, _) = broadcast::channel::<MonitoringEvent>(100);  // ❌ Only 100 slots
let (tx_app_broadcast, _) = broadcast::channel::<Vec<u8>>(100);
```

**Problem**: Si 1000 clients se connectent mais le channel n'a que 100 slots:
```
Mon client essaie d'envoyer un paquet
→ broadcast::send() attend un receiver
→ Mais tous les 100 slots sont pris par d'autres clients
→ **HANG** (deadlock potential) OU **panic!** si buffer overflow
```

**Fix**:
```rust
let (tx_monitor, _) = broadcast::channel::<MonitoringEvent>(10000);  // Augmenter
// Ou utiliser flume::unbounded() pour pas de limite
```

## **8. 🔴 Command Injection Risk — PHP Binary Lookup**

**Localisation**: `src/supervisor.rs` (lignes 10-20)

```rust
let php_bin = if Path::new("./php.exe").exists() {
    "./php.exe".to_string()
} else if Path::new("./php/php.exe").exists() {
    "./php/php.exe".to_string()
} else if Path::new("./bin/php.exe").exists() {
    "./bin/php.exe".to_string()
} else {
    "php".to_string()  // ❌ Recherche dans PATH
};

let mut child = Command::new(&php_bin)
    .arg("-S")
    .arg(format!("127.0.0.1:{}", port))
    .arg("router.php")  // ❌ Pas d'absolute path
    .spawn()
    .expect("Échec du lancement du serveur PHP");
```

**Attack Scenario**:
```bash
# Dans le répertoire du projet, attacker crée un symlink:
ln -s /bin/malicious_php ./php

# Ou si PATH manipulation:
export PATH=/tmp/attacker:$PATH
# Crée /tmp/attacker/php → malicious binary
```

**Recommandation**:
```rust
// Use absolute paths
let php_bin = which::which("php")?;  // Recherche sécurisée dans PATH
// OR
let php_bin = "/usr/bin/php";  // Hardcoded

// Always use absolute path for router.php
let router = std::fs::canonicalize("router.php")?;
```

## **10. 🟡 Type Cast Ambiguity — node_id Narrowing**

**Localisation**: `src/socket/mod.rs` (ligne 652-665)

```rust
let node_id = u16::from_be_bytes([data[offset], data[offset+1]]);
let op_type = data[offset + 2];
let version = u32::from_be_bytes([data[offset+3]..data[offset+7]]);
let data_len = u16::from_be_bytes([data[offset+7], data[offset+8]]) as usize;
offset += 9;

if data.len() < offset + data_len { break; }
let op_data = &data[offset .. offset + data_len];
```

**Bug**: Index `offset + 7` suppose que data est au moins 8 bytes depuis offset, **mais pas de check AVANT reading**.

**Fix**:
```rust
if data.len() < offset + 9 { break; }  // Check FIRST
let node_id = u16::from_be_bytes([data[offset], data[offset+1]]);
```
